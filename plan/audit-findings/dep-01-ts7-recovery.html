TypeScript 7 Recovery

Next.js 16.2.6 still resolves typescript/lib/typescript.js which TypeScript 7 removed. ignoreBuildErrors does not bypass setup, so PR45 cannot produce a reliable web build. The fix is to pin apps/web to TypeScript 5.9.3 and remove the workaround.

01

Problem

PR45 attempted a project-wide TypeScript 7 upgrade. The build fails because Next.js 16.2.6 still hard-references typescript/lib/typescript.js — a file that TypeScript 7 restructured and removed. The ignoreBuildErrors config option does not bypass the initial module resolution phase, so the web build cannot complete.

This has blocked the PR from merging and prevents any other change in apps/web from being verified through CI or local production builds.

Root cause Next.js resolves its own TypeScript instance during build setup. TypeScript 7 moved from a single-file CLI to a modular structure. The two projects have not yet aligned their release cycles.
02

Execution plan

Step 1 — Record the failed state

Document the exact error, the Next.js version, the TypeScript 7 commit, and the module resolution trace in the PR closing comment. This creates a concrete re-entry condition for the future.

Step 2 — Pin apps/web to TypeScript 5.9.3

In apps/web/package.json, set "typescript": "5.9.3" explicitly. Add a resolutions or overrides entry if hoisting causes TS7 to be selected for the web package. Non-Next packages (packages/*) may remain on the TS7 path.

Step 3 — Remove ignoreBuildErrors

In apps/web/next.config.ts, delete the typescript.ignoreBuildErrors: true line that was added to work around the TS7 incompatibility. Type checking will once again block erroneous merges.

Step 4 — Restore test-file type inclusion

Revert any exclude changes in apps/web/tsconfig.json that were introduced to hide TS7-incompatible test files. Test type coverage should match production coverage.

Step 5 — Regenerate lockfile and verify

Run bun install --frozen-lockfile (or pnpm equivalent), then all typechecks, next build, the full test suite, and a deployment preview. Validate that non-Next packages still compile under TS7.

Step 6 — Close PR45

Add the re-entry condition as a closing note: attempt TS7 again only when the supported Next.js release documents compatibility and a clean branch passes local and CI without patches or skipped validation.
