Problem

The prior full-scan snapshot scored 39 with 844 diagnostics (51 errors, 793 warnings) across 158 files. The large file surfaces dominate:

  • Explorer8,101 lines
  • Editor4,184 lines
  • Command palette3,056 lines
  • Sidebar2,947 lines

  • Multimodal input1,701 lines

The score of 39 is a prior snapshot — a fresh canonical rerun is required before using this as a baseline. Do not make decisions or track progress against a potentially stale number.

The useful targets are not all 341 effects, but the categories that cause real bugs:

  • Rules-of-hooks — conditional or looped hooks that break React's call-order guarantees.
  • Missing cleanup — subscriptions, intervals, or event listeners that accumulate on unmount.
  • Derived/effect-chained state — state computed in effect when useMemo or render-time derivation would work.
  • Monolith boundaries — components over 1,500 lines that should be split by state ownership and workflow.
Score gate A score above 80 counts only when the production build, interaction checks, cleanup review, and affected workflows remain clean. Do not suppress or mechanically relocate diagnostics.
02

Execution plan

Step 1 — Rerun the canonical full-app React Doctor scan

Before any changes, produce a fresh baseline. Document the exact command, version, and diagnostic counts. File the results as the scorecard against which all progress is measured.

Step 2 — Fix rules-of-hooks violations (errors)

These are the 51 errors in the snapshot and are the highest-leverage target. Each one represents a hook call that React cannot guarantee order for, leading to unpredictable state corruption. Fix pattern: move the hook outside the conditional/loop, or restructure to avoid conditional hook calls.

Step 3 — Add missing cleanup (warnings, high severity)

Every useEffect with a subscription, timer, DOM listener, or AbortController must return a cleanup function. Focus on components that mount frequently (modals, overlays, chat sessions). Missing cleanup in chat-related effects is the most likely source of stale closure bugs reported in user workflows.

Step 4 — Convert effect-chained state to derived state

Where state A changes → effect re-runs → sets state B, replace with useMemo or render-time computation. This eliminates an extra render cycle and makes data flow explicit. Focus on the largest files first (explorer, editor) where the pattern is most entrenched.

Step 5 — Split monoliths

Split components by state ownership and workflow, not by arbitrary line count. Each extracted module should own one coherent piece of state and have one reason to change. For the explorer (8,101 lines), this likely means separating file tree, search, filtering, and upload-progress into separate components.

Do not remove an export or dependency just because it appears unused in a static scan. Check runtime code paths (feature flags, dynamic imports, string references). Document intentional diagnostics with inline comments.

Codebase readability impact: Very high. The top 6 files account for 22,697 lines — roughly 30% of the frontend. Splitting them by responsibility makes the codebase navigable for new contributors, makes code review smaller and more focused, and enables parallel work on different parts of the same feature. The derived-state conversion replaces an implicit, two-step state update (change A → effect → set B) with an explicit, single-direction computation (B is derived from A). This is the single biggest readability improvement available in the React layer: data flow becomes traceable top-to-bottom instead of triggering side-effect cascades.

Performance improvement: Converting effect-chained state to useMemo directly reduces render count — one render instead of two (state change → effect runs → setState → second render). For component trees that derive 3–5 values from the same source, this can eliminate entire re-render cascades. Missing cleanup fixes eliminate accumulating event listeners that cause O(n²) event dispatch over time in long-lived sessions. These are the two most practically impactful performance changes available in the frontend; the rest are correctness and maintainability.

Validation

  • Fresh canonical React Doctor scan before and after — score must be 80+ with zero "error" category diagnostics.
  • Production build succeeds without warnings related to changed files.
  • Interaction checks pass for affected workflows (chat, file upload, editor, sidebar navigation).
  • Cleanup review: every changed useEffect with a subscription/timer/event listener has a returned cleanup function.
  • Render-count profiles for converted components show no regressions (ideally: fewer renders for the same interaction).
  • Monolith splits verified: each extracted component has one coherent responsibility, one set of tests, and no unexpected imports from sibling modules.
  • Deleted exports verified via production telemetry or import tracing — no false positives from static-only analysis.
