Avenire misconception system comparison

The current system is now both a durable misconception memory layer and a bounded current-turn signal detector. The detector embeds the latest user message, runs cosine similarity against active misconception text, classifies only likely hits, and injects a temporary prompt-memory block before the assistant response streams.

Short answer

The system now covers the plan's critical runtime path. Avenire stores misconceptions, tracks evidence, promotes candidates, injects active misconceptions into future prompts, adjusts retrieval, connects reviews to mastery, and runs a fast current-turn detector for known misconception territory.

The detector is intentionally non-persistent: it can improve the current answer by adding private guidance, while the existing session-summary and review paths remain responsible for durable evidence.

Current system

Database

Misconception records

`misconception` stores subject, topic, concept, reason, source, status, confidence, active state, evidence count, promotion time, and resolution time.

Evidence

Independent observations

`misconception_evidence` dedupes observations and lets repeated independent evidence promote a candidate into a confirmed active misconception.

Chat tools

Manual model capture

The assistant can log, list, improve, resolve, clear, and convert misconceptions into flashcards when the conversation clearly establishes a wrong model.

Session summary

Retrospective inference

Completed chat windows are classified for learning relevance and can persist up to three misconception candidates from the transcript.

Reviews

Flashcard feedback

FSRS review events can create candidates, decay confidence on good reviews, resolve misconceptions, and recompute concept mastery.

Retrieval

Learner-aware ranking

Retrieval candidates get boosted when their concept metadata matches active misconceptions or weak review stability.

Current flow

1

Chat turn

User reveals confusion, asks a concept question, or demonstrates a wrong model.

2

Capture

A chat tool logs it immediately, or the session summary infers it later.

3

Evidence

The database records status, confidence, source, evidence root, and timestamps.

4

Learning loop

Flashcard reviews reinforce, decay, resolve, or update concept mastery.

5

Current + future prompt

Active misconceptions can now influence the current response and later matching turns.

Plan comparison

What Avenire already has

A durable misconception memory graph. It is good at remembering what happened, deciding whether the signal is strong enough to be active, and using that state in later tutoring, retrieval, and study generation.

  • Multiple capture sources: chat tool, session summary, manual capture, review events.
  • Candidate and confirmed states with confidence and evidence count.
  • Private prompt memory for active misconceptions.
  • Review-driven decay and resolution.

What was added

A real-time detector before the main model call. It is bounded, selective enough to avoid classifier calls on unrelated messages, and temporary enough to avoid polluting durable memory.

  • Embeds the current user message with Cohere `embed-v4.0`.
  • Cosine pre-filters against active misconception concept/reason text.
  • Runs a small classifier only after the pre-filter passes.
  • Injects a one-shot intervention block into the current response.

Implemented changes

  1. Added `detectMisconceptionSignals` in `@avenire/ai/misconception-signals` with a thin web database adapter.
  2. Loads up to 32 active misconceptions for the resolved subject.
  3. Caches active misconception embeddings in-process by id, updated time, model, and text hash.
  4. Runs cosine pre-filtering before any classifier call.
  5. Calls `apollo-meta` only for likely hits above the classifier threshold.
  6. Runs the detector as optional prompt enrichment: a 900ms route budget skips the signal rather than blocking chat, while provider calls abort around 850ms.
  7. Injects the result as a temporary prompt-memory block for the current response only.
  8. Leaves durable evidence creation to existing session-summary and review paths.

Target shape

Keep the runtime signal separate from persistence. The signal can improve the answer now; the existing evidence pipeline can decide later whether it was a real misconception.

Implementation priority

Done

Pre-stream detector

The route now runs `detectMisconceptionSignals` before `streamText`, timeout bounds it, and appends the returned intervention block when matched.

Done

Misconception embedding cache

Active misconception embeddings are cached in-process for six hours using a key that includes misconception id, updated time, embed model, and text hash.

P1

Persistent vector cache

A database or Redis vector cache could make cold starts faster across server instances. The current implementation keeps the runtime lightweight and local.

P1

Provenance cleanup

Preserve signal source quality in evidence-level analytics. Do not rely on the top-level latest `source` field for source reliability.

P1

Subject drift handling

If a session moves from one subject to another, active misconception context should follow the new subject rather than staying tied to the original one.
