Misconception system chat startup implementation

Follow-up implementation notes for the comparison doc. The chat route now gets the UI moving before slow learning-context work, uses transient AI SDK data parts for visible progress, and removes one redundant ownership query on existing chats.

Implemented in /api/chat Shiki-style highlighted snippets Diff-oriented notes

What changed

Streaming

Transient startup activity

The route writes `data-agent_activity` before the model starts, so the frontend can show context preparation instead of waiting for the first reasoning token.

Latency

Learning context and detector moved behind response setup

Workspace subject lookup, recent summary lookup, misconception prompt memory, and real-time misconception predetection now run inside the UI stream executor.

Detector

Embedding and cosine prefilter

`detectMisconceptionSignals` embeds the latest user message, compares it with active misconception embeddings, classifies only likely hits, and injects a current-turn memory block.

Database

Writable chat lookup

Existing-chat validation uses one lookup that returns `readOnly` when the slug exists but is not owned by the requester, avoiding a second `isChatOwnerForUser` query.

New startup flow

1

Validate basics

Session, workspace, chat id, idempotency, billing, and user message persistence.

2

Create stream

The response stream is created before subject and misconception context are loaded.

3

Tell the UI

Transient `agent_activity` reports "Preparing chat context" and memory checks.

4

Load in parallel

Model-message conversion overlaps with bounded context, prompt-memory reads, and signal detection.

5

Start model

The route emits "Model response started" and merges the AI SDK UI message stream.

Database change

export async function getWritableChatBySlugForUser(
  userId: string,
  slug: string,
  workspaceId?: string | null,
) {
  const [thread] = await db
    .select()
    .from(chatThread)
    .where(and(eq(chatThread.slug, slug), eq(chatThread.workspaceId, workspaceId)));

  return thread ? { ...mapChatSummary(thread), readOnly: thread.userId !== userId } : null;
}

Notes

The embed-filter-classify path now lives in `@avenire/ai/misconception-signals` and is covered by unit tests. It uses a 900ms route budget, an 850ms provider abort, a 32-record active misconception cap, a 4-candidate classifier cap, and six-hour in-process embedding caching. The timeout does not make chat fail; it only skips this optional current-turn prompt enhancement when the detector is too slow.

Touched code paths: `apps/web/src/app/api/chat/route.ts`, `packages/ai/misconception-signals.ts`, `packages/ai/misconception-signals.test.ts`, `apps/web/src/lib/misconception-signal-detector.ts`, `apps/web/src/lib/chat-data.ts`, and `packages/database/src/chat-data.ts`.
